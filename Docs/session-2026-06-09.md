## 2 — Wave previews (commit `868002a` + cleanup)
Old model: next wave waited for *all* pieces to land; previews = the single next
wave, shown after clearing the top cell; tapping consumed them → you could go
blind, and you could **freeze a desired ingredient forever** by tapping the others.

New model:
- **Standing preview queue**: target count (= next wave size) always reserved and
  shown, one per column, topped up every frame; seeded at `StartSpawning`.
- **Previews ARE the next wave** — consumed on the original wave's landing.
- **Lock-cheat killed**: tapped previews are *fire-and-forget* — NOT added to the
  wave-completion list, so the gate depends only on the original wave landing
  (un-stallable). A held preview force-drops within ~one fall.
- **Visual clearance is decoupled from selection**: column choice stays unbiased
  (random, one-per-column, height ignored); `AnimConfig.PREVIEW_SPAWN_CLEARANCE`
  only delays the *ghost's* reveal so it never overlaps a falling sprite.
- Collapsed `WaveFalling`/`WaitingForLand` into one state; unified wave
  composition onto the queue (removed `RollWave`, `GetUnusedColumn`,
  `WaveClearedTop`, `ShowPreviews`, `HasPreviews`, `_nextWaveData`).

## Key decisions & non-obvious findings
- **Renaming a sprite ≠ renaming its sub-asset.** The fold-out child sprite name
  lives in the `.png.meta` in 3 spots (`internalIDToNameTable.second`,
  `spriteSheet.sprites[].name`, `nameFileIdTable` key); the `internalID`/fileID is
  stored explicitly, so editing the name preserves it. Now in CLAUDE.md → Asset
  Conventions.
- **The "full column" preview rule was a no-op.** `IsOverflowing` = `MAX_ROWS`
  = the game-over height, so a column is only "full" once you've already lost.
  Nothing biases placement toward emptier columns — pieces rain onto tall columns.
- **Clearance leaking into selection caused near-strict A,B↔C,D alternation**
  (easiness). Fixed by reserving the preview slot immediately but keeping the
  ghost hidden until its column clears — selection unaffected, visual delayed.
- First wave is seeded up front but **hidden through the initial delay**
  (`RevealCleared` only runs in `WaveFalling`), so behavior matches the old path.
