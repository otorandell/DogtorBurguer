## Text fill + border — Known Issue RESOLVED (playtested, renders)
The reference look for HUD numbers and all red-box labels is **cream fill `#FCFAF1` + thick
dark-brown border `#492611`** (sampled from IMG_1645 at full res — at small scale the digits *look*
dark-filled, they aren't).

- **Mechanism**: `UIFactory.StyleFillAndBorder(tmp, fill, border, width)` — clones the font's
  material once per style (cached per font+color+width, shared across texts → batched),
  `EnableKeyword(ShaderUtilities.Keyword_Outline)`, sets `ID_OutlineColor`/`ID_OutlineWidth`,
  assigns via `fontSharedMaterial`, then `UpdateMeshPadding()`. This sidesteps the broken
  per-component `tmp.outlineWidth` path entirely (those setters are now deleted from
  `AddStyledText` — they never rendered).
- **Convenience**: `UIFactory.StyleHudText(tmp)` applies the standard palette from
  `UIStyles.HUD_TEXT_FILL / HUD_TEXT_BORDER / HUD_TEXT_BORDER_WIDTH` (0.25, live-tune knob).
- **Applied to 5 texts**: Level/Score big numbers, Level/Score tab words, SPECIAL ORDER banner,
  x-mult badge, consumable count. Old cream constants (`HUD_TITLE_LABEL_COLOR`,
  `CONSUMABLE_COUNT_COLOR`) deleted — one source of truth.
- **Size bumps** (auto-fit protected): panel numbers 30→54, tab words 12→22, banner 13→18,
  mult badge 20→24, count 22→26.
- Top-bar pill numbers stay plain dark brown — renamed `TOPBAR_NUMBER_COLOR` (matches reference).
- **Left open**: `WorldTextFactory` (world-space popups) still uses the old broken setters —
  migrate the same way if world outlines are wanted.
