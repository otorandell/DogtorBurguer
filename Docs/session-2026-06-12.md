# Session Context — 2026-06-12 (Phase 2 Polish: Consumables system — the last big system)

Phase 2 (Polish & Final). Branch: `polish`. Designed and implemented the **Consumables**
system end-to-end (the planned final system), reframing the old GemPack drops into **Burger
Fairies** that carry gems *or* a consumable. Design of record: `Docs/consumables-design.md`.

## Headline
A fairy flies across the screen carrying a payload (gems ~40% / consumable ~60%). Tap to
collect; consumables go to a 2-slot per-run inventory in the score panel. Drag a slot icon onto
a column to use it: a fast faller drops and resolves on impact.
- **Ketchup** → clears the whole targeted column.
- **Mustard** → removes the targeted column's top type **board-wide** (+ cascades).
- **Skewer** → drives one bottom bun to the floor, destroys the rest, regulars collapse on top.

## Key decisions
- **Per-run inventory**, 2 slots, FIFO-evict-oldest. Not persisted, not buyable (kept scope tight).
- **Unified faller**: all three are the same "fast-fall, resolve on impact" entity; reaching the
  floor with no target **fizzles** (item still spent). Uniform behavior; closed the "what falls
  for Ketchup/Mustard" and empty-column questions at once.
- **World keeps moving while carrying** — a cancellable pause would be a free stop-time exploit.
- **Cancel on release outside the playfield** (item retained); use only on release over it.
- **Scoring**: non-bun removals score flat (10/ea), no multiplier (match-like); **buns never
  score** via consumables. Mustard chain reactions reuse the existing pair-match cascade — no
  new logic; the "always pairs, odd-one-remains" rule handles multi-stacks.
- **Art**: one badge sprite per payload (Resources/Rewards) does quadruple duty (fairy badge /
  icon / ghost-alpha / faller); `SpriteFit` normalizes by world-height. Fairy carrier in
  Resources/Fairy.
- **Polymorphism** for effects (target rule + on-impact), grid mechanics in `GridManager`.
